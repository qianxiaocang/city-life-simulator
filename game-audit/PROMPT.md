# 给修复 AI 的开场指令（整段复制给对方的第一个消息）

你正在接手一个中文人生模拟游戏的**历史真实性与机制缺陷修复**任务。本目录是完整工作区，可直接运行。

## 你必须先做的三件事（顺序不可调换）

1. 读 `life-sim-fix-guide.md` 的 **§0 元指令**、**§1.4 度量陷阱**、**§7 先修度量再修游戏**。
2. 用 GAME_SRC 指向真实游戏模块目录，跑源码核对 + 基线：
   ```bash
   GAME_SRC=/你的仓库/src node verify-repo.mjs     # 18 条锚点必须全 PASS
   GAME_SRC=/你的仓库/src N=2000 node run-audit.mjs
   GAME_SRC=/你的仓库/src node verify.mjs          # 会打印校验分母
   ```
   出现 FAIL/MISSING 就先停下来，把差异报给我，不要直接照指南改。
3. 按 **§8 路线图的 B0** 先补校验器（断言必须报告分母、年代比较固定性别且每格 ≥30 种子），
   产出基线快照后再动 B1。**不要跳过 B0**——上一轮审计有 5 条"缺陷"其实是校验器自身的 bug（§1.4、§10）。

## 硬规则

- **禁止只改文案**。P0 全是 `src/data/development.js`、`src/engine.js`、`src/education.js`、`src/economy.js` 的数值与闸门问题。
- **禁止改 §9「已验证正常」清单**里的行为（养老金替代率 p50=0.38、16 岁用工闸门 0/3943 违规、时间线一致性、1981 年后寿命曲线、事件可达性）。要改必须先给反证。
- **§1.1 的口径不要改口**：本审计用游戏自带引擎无头对局 13.7 万局，不是浏览器逐局点击 1 万次。对外结论必须保留这条披露。
- 数值以 §6 八张重标定表为准；表中带「待补录」标记的（§11）在代码注释里保留 `modelOnly` 标注，不要伪装成官方观测。
- 每完成一批：跑 `node run-audit.mjs`（N=60000）+ `node exp3-divergence.mjs`，把该批每条断言的
  `pass/fail + 实测值 + 分母` 写进提交说明。**已达标项回退即视为该批未完成。**
- 遇到断言无法通过，先判断是"代码没改对"还是"断言本身口径错了"（本项目两种都真实发生过），不要为了绿灯放宽断言。
